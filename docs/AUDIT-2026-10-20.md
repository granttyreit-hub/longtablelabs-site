# longtablelabs.com audit — 2026-10-20

By Science Officer WEB · Site, on commissioning. Checked: every page and asset
in the repo, the local preview (`node serve.js`, desktop and 375 px), the live
site headers, every external link, and the app repo's charter for the facts
behind 1.0.9.

Verdict: the site is well built (fast, accessible skeleton, no third-party
requests, no dead links) but its **Cadent Family content is two months
stale**. It still says the app is "not yet in any store", has a "Notify me at
launch" email form as its main call to action, and knows nothing about the
membership, contact links, kid mode or chores-with-points. Echo Night's card
is current as of today.

## B. Missing

- B1 **Store link / badge.** No link to the Play listing anywhere. A real
  "Get it on Google Play" badge is now permitted (it links to a live listing).
- B2 **Pricing.** No statement that the app is free with a 3-import trial and
  a $1.99/month membership for 10 imports (roll over to 20). Play requires the
  in-app purchase to be described honestly; the website should match.
- B3 **Dedicated product pages.** Cadent and Echo Night live only as anchors on
  the home page. `/cadent` and `/echo-night` pages would give the store
  listings, TikTok bio and house ads a clean link target.
- B4 **Social links** in the footer (TikTok, YouTube).
- B5 **Open Graph / Twitter card meta** — none. Links shared on TikTok,
  Discord or chat unfurl with no image. Needs one 1200×630 image per page
  (can be composed from existing marks; no AI generation needed).
- B6 **`robots.txt`, `sitemap.xml`, canonical links** — none. Low effort.
- B7 **`404.html`** — GitHub Pages serves its generic 404 (seen on `/add/…`).
  A branded 404 that explains "contact links live on link.longtablelabs.com"
  would catch anyone who types the apex form.
- B8 **Echo Night support.** `support.html` is Cadent-only; Echo Night's
  privacy page points at support@ but the support page never mentions the
  game. Play will want a support URL for Echo Night too.
- B9 **Videos.** The two finished daily demos (`video-studio/final/01…`,
  `02…`) are not on the site; a short "See it in action" row linking to the
  TikTok/YouTube posts (or embedding the mp4s locally) is cheap.
- B10 **Favicon set.** Only an SVG icon; no `apple-touch-icon`, no PNG
  fallback, no `manifest`. Minor.

## C. Accessibility

- C1 Good: skip link, `lang`, landmarks, `aria-label` on navs, focus-visible
  styles, reduced-motion handling for the video, alt text on every image,
  `aria-pressed` sound toggle.
- C2 **Heading order:** `index.html` has two `<h1>` ("Everyone to the table."
  and "Every family runs on paper."). Make the Cadent one an `<h2>` styled as
  display, or accept it.
- C3 **Contrast:** `.cta-note` and `.store .when` use `--ink-faint #9a838b` on
  blush `#fdeadf` ≈ 3.2:1, below AA for small text. `.fineprint` in the
  footer likewise. Darken `--ink-faint` one step.
- C4 **Email label** uses an inline `left:-9999px` hack; the `.visually-hidden`
  class it names does not exist in `styles.css`. Add the class.
- C5 **Emoji icons** (📷 ✓ 🔒 👨‍👩‍👧 🔄 🗒️ 🤖 🪟 🍏) are `aria-hidden`, fine, but
  render differently per platform; the Windows preview shows them as flat
  glyphs. Optional: inline SVG.
- C6 `<video autoplay loop muted>` has an `aria-label` but no captions track;
  the narration is only available by turning sound on. Add a `<track kind="captions">`
  (a WebVTT file from the existing `script.md`) — accessibility and
  muted-autoplay both benefit.

## D. Mobile

- D1 At 375 px the primary nav wraps to two lines beside the brand (seen in
  the preview). Acceptable, but a tighter rule (`gap`, smaller font below
  400 px, or hide "Privacy" into the footer) would clean it up.
- D2 Hero screenshot frame is `aspect-ratio 9/19.5` with `object-fit: cover`;
  1080×2400 captures (9/20) are cropped slightly at top/bottom. Fine.
- D3 Product cards stack and centre below 560 px — good.
- D4 No horizontal overflow found on any page.

## F. Links

All external links return 200: anthropic.com/legal/privacy,
policies.google.com/privacy. All internal anchors resolve. No dead links.
`https://longtablelabs.com/add/<code>` is 404 by design (A15).

## G. Security / hygiene

- No scripts beyond the two inline ones; no forms post anywhere (mailto only).
- No `Content-Security-Policy` or `Referrer-Policy` meta; GitHub Pages lets
  you set neither as headers, but a `<meta http-equiv>` CSP is possible.
  Low value for a static site; skip unless asked.
- `serve.js` is git-ignored despite being in the repo listing (it was added
  before the ignore rule); harmless.
